# RAG 项目面试说明

## 一分钟介绍

这个项目把四种格式的个人资料整理成可检索知识库。我把检索和生成分开，使用 BGE 句子级子块检索、返回父块做上下文，融合字符 BM25 与向量排名。工程上统一了重建和加载入口，采用新集合构建后原子切换清单，避免重建的是 MiniLM、查询却读取旧 BGE 库的问题。用稳定块 ID 保留来源，并检查回答引用的证据编号。

开发集是 200 道库内和 200 道库外问题，其中块级召回只计 198 道单块问题。新版 RRF R@5 为 83.8%，BM25 82.3%，子块向量79.3%。我没有把开发集成绩称为独立测试，也没有把拒答准入准确率称为最终答案准确率。新增 64 道固定配置挑战题后，发现规则闸门对长问法和同领域硬负例泛化不足，这是后续要修的主要问题。

## 核心问题

**为什么使用父子块？** 小块便于匹配单一主题，父块提供完整上下文。按 parent_id 聚合最近距离，避免同一父块占多个候选。查询归一化和建库一致；归一化向量的 L2 平方距离范围与旧 MiniLM 未归一化向量不同，阈值不能直接复用。

**为什么使用 RRF？** 两个通道分数量纲不同，按名次融合避免直接相加。权重固定为0.45，RRF常数60。它不是普遍优于 BM25：新增挑战集 BM25 R@5 90.6%，RRF84.4%。相关性强的候选排在前列并不等于能回答问题。

**为何不先加 reranker？** 当前首先需要解决索引一致性、数据隔离与可靠来源。重排能调整候选次序，不能自动修复缺失证据、错误标注或阈值泛化问题。后续应在更大领域语料上用对照实验判断收益。

**重复导入、删除怎么处理？** 当前实现幂等全量重建。相同语料和配置复用版本；改变语料后先写新集合，条数校验成功才切换 manifest。旧版本保留，活动版本不再包含删除文件。尚未实现按文档增量重算、并发写锁与自动垃圾回收。

**如果构建到一半崩溃？** 当前清单不变，读取者继续使用上一个成功版本；可能遗留未激活的 staging 集合。构建尚不支持多个进程同时竞争写入，应单写者运行。

**引用能证明没有幻觉吗？** 不能。当前能从编号追踪到块、路径和已有页码，并拒绝不存在的编号。编号有效性不等于语义支持关系，尚未宣称真实 LLM 的 Citation Precision 或最终回答准确率。

**如何处理拒答与模型错误？** 检索闸门拒绝时不调用 LLM；LLM 明确表示证据不足时返回另一状态；API 失败和无效引用分别记录。不会把网络错误算成知识库拒答。

**当前最重要的不足？** 小规模个人语料；原问题集反复调参；挑战题由助手编写且与已有资料共享事实；闸门在新问法上不稳；尚未做真实生成质量与外部语料验证。

## 指标答法

- R@5：前5个父块中是否出现单一 gold；198道 fact/para，不包含2道 cross。
- MRR@5：首个 gold 的倒数名次，top5以外记0；三个方法统一截断。
- FRR：有答案却被检索闸门拒绝；FAR：没有答案却放行。指标只评价闸门。
- 性能：包含查询编码、向量检索、BM25及融合的预热后逐条耗时，不包括 LLM。
- 可复现：固定参数，记录代码/语料/题集哈希、索引版本、包版本、逐题排序和判定。

## 演示顺序

1. `python -m rag.index --from-snapshot`，再次执行展示复用。
2. `python app.py -q "Agent 有哪四个核心部件？" --retrieve-only`，展示证据编号与原文。
3. `python -m eval.run_release --dataset development`，展示基线与统一口径。
4. `python -m eval.run_release --dataset challenge`，解释真实失败而不是只展示成功。
5. `python -m unittest discover -s tests -v`，展示关键回归。

不要把当前系统描述成经过大规模企业部署，不要承诺“保证腾讯面试通过”。应能自己解释实现、复现结果并说明取舍。
